## Context

JustNewTab 是一款多浏览器新标签页扩展，使用 Svelte + TypeScript + Tailwind CSS 构建。当前样式系统存在以下问题：

**当前状态**:

- 样式分散在 `src/styles/bookmark-area.css` 和各组件的 Tailwind 类名中
- 颜色值硬编码在各处，缺乏统一管理
- 设计风格不一致，缺乏品牌识别度

**参考设计**: 小米 MiMo 网站设计风格

- 深色主题，高对比度，科技未来感
- 橙色/珊瑚色作为品牌点缀色
- 大面积留白，呼吸感强
- 圆角矩形组件，柔和阴影
- 极简主义 + 品牌叙事性

**约束条件**:

- 必须保持 Manifest V2/V3 兼容性
- 不能引入新的 CSS 框架依赖
- 需要保持响应式设计
- 扩展体积影响最小化

## Goals / Non-Goals

**Goals:**

- 建立统一的设计令牌系统（Design Tokens）
- 定义清晰的颜色、字体、间距、圆角、阴影规范
- 重构现有组件样式以符合新设计规范
- 提升深色主题的视觉层次和对比度
- 统一动画和过渡效果

**Non-Goals:**

- 不改变现有功能逻辑
- 不添加新的 UI 组件
- 不引入新的 CSS 框架
- 不支持亮色主题
- 不改变组件的交互行为

## Decisions

### 1. 设计令牌实现方式

**决策**: 使用 CSS 自定义属性（CSS Variables）实现设计令牌

**理由**:

- 原生浏览器支持，无运行时开销
- 可在 Tailwind CSS 中直接使用
- 支持动态主题切换（未来扩展）
- 调试方便，可在浏览器开发者工具中实时修改

**替代方案**:

- Tailwind 配置扩展：灵活性不足，难以动态切换
- JavaScript 对象：增加运行时开销
- CSS-in-JS：与现有技术栈不符

### 2. 颜色系统设计

**决策**: 基于 Royal Indigo Night 配色建立深色主题颜色系统

**颜色层级**:

- 背景色：slate-950（最深）→ slate-900 → slate-800 → slate-700
- 文本色：white（主文本）→ slate-300（次文本）→ slate-400（辅助文本）→ slate-500（占位文本）
- 品牌色：Royal Indigo Night 配色组
  - #1A237E（最深）
  - #283593（深）
  - #303F9F（中）
  - #3F51B5（主品牌色）
  - #5C6BC0（浅）
- 语义色：success（绿）、warning（黄）、error（红）、info（蓝）

**理由**:

- 保持与 Tailwind slate 色系的兼容性
- Royal Indigo Night 配色提供专业的深蓝色调
- 深蓝色与深色主题完美融合
- 语义色遵循行业标准

### 3. 字体系统

**决策**: 使用系统字体栈 + 本地字体回退

**字体层级**:

- 标题：大号粗体无衬线字体
- 正文：中等字号无衬线字体
- 辅助：小号字体

**理由**:

- 系统字体加载快，无额外网络请求
- 跨平台一致性好
- 符合 MiMo 的极简风格

### 4. 间距和圆角系统

**决策**: 使用 Tailwind 默认间距比例 + 自定义圆角

**间距**: 基于 4px 网格（Tailwind 默认）
**圆角**:

- 小组件：rounded-lg（8px）
- 卡片：rounded-xl（12px）
- 大容器：rounded-2xl（16px）

**理由**:

- 与 Tailwind 生态系统一致
- 圆角层级参考 MiMo 的柔和风格

### 5. 阴影和动画系统

**决策**: 定义统一的阴影和动画变量

**阴影层级**:

- 轻微：shadow-sm
- 标准：shadow-md
- 显著：shadow-lg
- 悬浮：shadow-xl

**动画**:

- 过渡时间：150ms（快速）、200ms（标准）、300ms（缓慢）
- 缓动函数：ease-in-out（标准）

**理由**:

- 阴影层级提供视觉层次感
- 统一的动画时间保持交互一致性

## Risks / Trade-offs

| 风险                     | 影响 | 缓解措施                     |
| ------------------------ | ---- | ---------------------------- |
| CSS 变量在旧浏览器不支持 | 低   | 使用 PostCSS 插件提供回退值  |
| 样式重构可能引入视觉回归 | 中   | 逐步重构，每次重构后视觉测试 |
| 设计令牌过多增加维护成本 | 低   | 保持令牌数量合理，定期审查   |
| Tailwind 配置冲突        | 低   | 使用 extend 而非覆盖默认配置 |

## 浅色主题设计

### 6. 浅色主题配色方案

**决策**: 使用 Ocean Depths 配色方案作为浅色主题品牌色

**配色**:

- #1565C0（最深蓝）
- #1976D2（深蓝）
- #42A5F5（中蓝）
- #90CAF9（浅蓝）
- #29B6F6（亮蓝）
- #81D4FA（最浅蓝）

**背景色层级**:

- 最浅背景：白色（#ffffff）
- 次级背景：浅灰（#f8fafc）
- 中等背景：中灰（#f1f5f9）
- 提升背景：深灰（#e2e8f0）

**文本色层级**:

- 主文本：深色（#0f172a）
- 次文本：中灰（#334155）
- 辅助文本：灰色（#64748b）
- 占位文本：浅灰（#94a3b8）

**理由**:

- Ocean Depths 配色提供清新的蓝色调
- 与深色主题的 Royal Indigo Night 形成对比
- 蓝色在浅色背景上具有良好的可读性
- 保持品牌一致性（都使用蓝色系）

### 7. 主题切换实现

**决策**: 使用 CSS 类名切换实现主题切换

**实现方式**:

- 在 `<html>` 元素上添加 `data-theme="light"` 或 `data-theme="dark"` 属性
- 使用 CSS 选择器 `[data-theme="light"]` 和 `[data-theme="dark"]` 定义不同主题的变量
- 默认主题为深色（向后兼容）

**理由**:

- CSS 类名切换性能好，无闪烁
- 可以通过 JavaScript 动态切换
- 支持系统主题偏好检测（`prefers-color-scheme`）
- 易于扩展更多主题

### 8. 主题持久化

**决策**: 使用 localStorage 保存主题偏好

**实现方式**:

- 保存用户选择的主题到 `localStorage.getItem('jnt-theme')`
- 页面加载时读取并应用保存的主题
- 如果没有保存的偏好，检测系统主题（`prefers-color-scheme`）

**理由**:

- localStorage 持久化，刷新后保持
- 支持系统主题检测，提供更好的默认体验
- 实现简单，无额外依赖

## Migration Plan

1. **准备阶段**
   - 创建设计令牌文件 `src/styles/tokens.css`
   - 扩展 Tailwind 配置以使用设计令牌

2. **实施阶段**
   - 按组件逐步重构样式
   - 每个重构后进行视觉测试
   - 记录修改内容

3. **验证阶段**
   - 在不同浏览器中测试
   - 检查响应式布局
   - 验证深色主题可读性

4. **回滚策略**
   - 使用 Git 版本控制
   - 每个重构独立提交
   - 可随时回退到任意重构点
