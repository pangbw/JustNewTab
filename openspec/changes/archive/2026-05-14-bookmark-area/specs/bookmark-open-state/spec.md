## 新增需求

### 需求：检测已打开的标签页

系统应检测哪些书签当前已在浏览器标签页中打开。

#### 场景：查询已打开的标签页

- **当**书签区域加载或标签页被打开/关闭时
- **则**系统查询所有已打开的浏览器标签页，并将其 URL 与书签 URL 进行比对

#### 场景：URL 匹配

- **当**比对标签页和书签时
- **则**系统在匹配 URL 时忽略协议（http/https）、尾部斜杠和锚点片段

#### 场景：实时更新

- **当**标签页被打开或关闭时
- **则**系统在 500ms 内更新受影响书签的打开状态

### 需求：高亮已打开的书签

系统应以视觉方式高亮当前已在浏览器标签页中打开的书签。

#### 场景：已打开书签的样式

- **当**书签被检测为已打开状态
- **则**系统应用醒目的视觉样式（如彩色边框、背景高亮、加粗标题）

#### 场景：多个标签页打开相同 URL

- **当**多个标签页的 URL 与某书签相同
- **则**系统仍然只将该书签标记为已打开（仅显示一次）

#### 场景：高亮动画

- **当**书签的打开状态发生变化时
- **则**系统显示平滑的过渡动画

### 需求：关闭标签页按钮

系统应在当前已打开的书签上显示关闭按钮。

#### 场景：关闭按钮可见性

- **当**书签被检测为已打开状态
- **则**系统在书签右侧显示关闭图标（X）

#### 场景：关闭按钮定位

- **当**关闭按钮显示时
- **则**系统将其放置在书签项的右边缘，垂直居中

#### 场景：关闭按钮悬停效果

- **当**用户将鼠标悬停在关闭按钮上
- **则**系统以醒目的悬停效果高亮该按钮

### 需求：关闭标签页操作

系统应在用户点击关闭按钮时关闭对应的浏览器标签页。

#### 场景：点击关闭标签页

- **当**用户点击已打开书签上的关闭按钮
- **则**系统关闭对应的浏览器标签页并移除打开状态高亮

#### 场景：关闭确认

- **当**用户点击关闭按钮
- **则**系统立即关闭标签页，无需确认（遵循标准浏览器行为）

#### 场景：关闭错误处理

- **当**系统关闭标签页失败（如权限不足）
- **则**系统显示错误信息："关闭标签页失败"

### 需求：标签页 Store 管理

系统应维护一个当前已打开标签页 URL 的 Store。

#### 场景：初始化标签页 Store

- **当**扩展加载时
- **则**系统查询所有已打开的标签页并填充标签页 Store

#### 场景：标签页创建时更新

- **当**新标签页被创建时
- **则**系统将该标签页 URL 添加到标签页 Store

#### 场景：标签页关闭时更新

- **当**标签页被关闭时
- **则**系统从标签页 Store 中移除该标签页 URL

#### 场景：标签页 URL 变化时更新

- **当**标签页的 URL 发生变化（页面导航）
- **则**系统相应地更新标签页 Store

### 需求：性能优化

系统应优化标签页检测以确保性能。

#### 场景：防抖更新

- **当**多个标签页事件快速连续触发时
- **则**系统对标签页 Store 更新进行防抖处理（500ms 延迟）

#### 场景：高效 URL 查找

- **当**检查书签是否已打开时
- **则**系统使用 Set 数据结构实现 O(1) 的 URL 查找

#### 场景：条件性轮询

- **当**书签区域不可见时
- **则**系统暂停标签页检测以节省资源

### 需求：跨浏览器兼容性

系统应在 Chrome、Edge 和 Firefox 中保持一致的行为。

#### 场景：Chrome 标签页 API

- **当**在 Chrome 中运行时
- **则**系统通过 webextension-polyfill 使用 chrome.tabs API

#### 场景：Firefox 标签页 API

- **当**在 Firefox 中运行时
- **则**系统通过 webextension-polyfill 使用 browser.tabs API

#### 场景：权限处理

- **当**未授予 tabs 权限时
- **则**系统优雅地禁用打开状态功能，并显示权限提示
